There's an escape code from DEC's VT420 that lets a program read your terminal's screen, one character at a time. Most terminals stopped answering it years ago. Git Bash's window never has, and neither have WezTerm's stable release or the xterm in Debian and Ubuntu 24.04.

So if you SSH somewhere from one of those, the box at the other end can read what was on your screen before you connected. That only matters for boxes you don't fully trust, like a shared server or one that's been broken into, but they're exactly where you don't want your laptop's `.env` turning up. Here's Git Bash, with a Debian server at the other end reading back the `.env` I'd just catted, and a file I'd closed in nano before that:

## One cell at a time

The code is DECRQCRA, "request checksum of rectangular area". A program prints `ESC [ id ; page ; top ; left ; bottom ; right * y`, and the terminal adds up the characters in that rectangle and sends the total back. Terminals mostly have it for test suites: draw something, ask for the checksum, check it came out right.

Make the rectangle a single cell, though, and the total is just that one character. Git Bash's window is mintty, and mintty sends the total back negated. This is what came back for the top-left cell above:

```text
ESC P 1 !~ FF9C ESC \
```

`FF9C` is minus `0x64`, which is `d`, the start of `dev@laptop`.

Ask about every cell and you've got the screen. The question goes down the SSH connection like any other output, and your terminal types its answer into the same place your keystrokes go, so ssh carries it back up. My script for it is about 40 lines of bash. It turns echo off at the server's end, so nothing shows while it reads, and it took 77 seconds to get through all 1,920 cells of an 80 by 24 window. Bold and underlined letters come back slightly off unless you allow for them, but plain ASCII comes through exactly.

It can't reach your scrollback, mind.

## The file you closed

nano and vim draw on a second screen, the alternate screen, and switch back to the normal one when you quit. What they drew is still there afterwards, in all three terminals that answer. So the script flips over to the alternate screen with `ESC [ ? 47 h`, which doesn't clear it, and reads that too. The `clear` I'd run after closing nano didn't touch it:

```text
  GNU nano 8.6        ~/.pgpass

prod-db.internal:5432:*:admin:correct-horse-battery-staple
```

That half isn't silent. Your old nano screen is back up while it's being read, so you'd probably notice.

## Who still answers

Upstream [xterm](https://invisible-island.net/xterm/manpage/xterm.html#VT100-Widget-Resources:disallowedWindowOps), the one everybody copies, puts the checksum on a short list of "dangerous" operations it refuses unless you say otherwise. Debian doesn't use that list. Its xterm package compiles in an older one of its own, which doesn't mention the checksum, so it's allowed. That's Debian 12, Debian 13 and Ubuntu 24.04, and Ubuntu 24.04's xterm gave up the same screen over SSH, nano and all. Debian's xterm has [refused every window operation](https://sources.debian.org/src/xterm/412-1/debian/changelog/) since last November, so Ubuntu 26.04 and Debian testing are fine.

Windows Terminal has it [behind a setting](https://github.com/microsoft/terminal/blob/main/doc/cascadia/profiles.schema.json), and [compiles it out](https://github.com/microsoft/terminal/blob/main/src/features.xml) of the console window built into Windows, because "conhost has no way to turn it off". iTerm2 asks you before it answers. Ghostty only added it in [1.4](https://ghostty.org/docs/install/release-notes/1-4-0), last week, and its config says why it's off:

<Quote
  by="Ghostty 1.4's config"
  href="https://github.com/ghostty-org/ghostty/blob/v1.4.0/src/config/Config.zig#L3073-L3086"
>
  This is disabled by default because a program can ask for the checksum of one cell at a time and
  so read back everything on the screen, including the output of other programs.
</Quote>

WezTerm turned it off in March, in [#7701](https://github.com/wezterm/wezterm/pull/7701), but hasn't made a release since February 2024. Homebrew, Scoop and Chocolatey all still install that one, and it answers. On Homebrew it's had 6,349 installs in the last 90 days, to nightly's 1,359.

## Built to pass a test

mintty and WezTerm got it the same way. esctest, a test suite for terminals, checks what a terminal drew by asking for checksums, so to pass it you had to answer. WezTerm [added it](https://github.com/wezterm/wezterm/commit/6cbb3ba43) for esctest in March 2019, dropped esctest five days later, and kept the checksum. mintty added it that July, "supporting esctest suite", says [its changelog](https://github.com/mintty/mintty/blob/master/wiki/Changelog.md).

It's not exactly a secret. In March 2023, in a [Windows Terminal issue](https://github.com/microsoft/terminal/issues/14974), j4james listed mintty and WezTerm among the terminals that answer by default. That September, [dgl's write-up](https://dgl.cx/2023/09/ansi-terminal-security) on terminal escape bugs described this exact attack, reading the screen before someone SSHes out, and reckoned the few terminals that support it "either prompt the user or have it disabled". Two of the CVEs in that write-up were mintty's, and the release that fixed the second one also fixed a DECRQCRA bug. It stayed on.

## Checking yours

Paste this into bash. It clears the screen, prints an X, and asks the terminal what's in the top-left cell:

```sh
clear; echo X; s=$(stty -g); stty -echo -icanon; printf '\e[1;1;1;1;1;1*y'; read -rs -t 1 -d '\' r; stty "$s"; echo "${r:5:4}"
```

`FFA8` or `0058` means it read the X back. Nothing, or `0000`, means it didn't.

For Git Bash, run it in Windows Terminal instead of its own window. The Git for Windows installer can add a profile for it if you tick the box, and Windows Terminal's default answer is always `0000`. Otherwise, open a fresh Git Bash window before you SSH anywhere you don't trust, since `clear` doesn't touch the alternate screen. On WezTerm, nightly has the fix. On Debian's or Ubuntu's xterm, add Debian's newer setting to `~/.Xresources` and run `xrdb -merge ~/.Xresources`:

```text title="~/.Xresources"
XTerm*disallowedWindowOps: *
```
